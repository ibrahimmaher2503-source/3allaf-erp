# 12 — Acceptance Criteria

## TSK-004B Criteria

AC-UI-06 through AC-UI-15 cover persistent controls, per-user preferences, screen detection, permission-aware guidance, approved flows, accessible tours, sensitive-data protection, RTL/LTR responsive behavior, missing-guide fallback, and no business side effects. The detailed contract is in `docs/40-contextual-page-guide-specification.md`.

## Acceptance Contract

All criteria are `Not Started` and require future manual evidence. Unless a criterion explicitly says otherwise: the actor is authenticated and server-authorized; branch/store/activity scope is enforced; inputs are server-validated; double submission and concurrent races are safe; successful sensitive changes are audited with source/reason/before-after; failures make no partial stock/financial/ledger effect; UI preserves recoverable input and shows localized feedback; lists are bounded/paginated; and relevant screens support default/loading/empty/error/success/disabled/permission-denied, Arabic RTL, English LTR, and responsive behavior.

## Master Data and Pricing

| ID | Given | When | Then | Failure / Permission / Audit / Print |
|---|---|---|---|---|
| AC-MD-01 | An authorized Administrator and approved master inputs. | The user creates/changes company, numbering, tax, methods, printers, branches, stores, drawers, roles, categories, brands, suppliers, price lists, or customer policy. | The validated scoped master is stored and visible in its UI; referenced history remains unchanged. | Unauthorized/duplicate/unsafe delete is blocked; sensitive setting change is audited; print preview applies where configured. |
| AC-MD-02 | A product and supplier/barcode context. | A product is created or its preferred supplier changes. | Internal item code remains stable; supplier barcode is stored when supplied or a local barcode may be generated independently. | Duplicate/reassigned code/barcode or item-code change is blocked/audited. |
| AC-MD-03 | Approved local supplier code and next serial policy. | A local barcode is requested. | Value follows four supplier digits plus six serial digits and remains independent from item code. | Invalid/duplicate/exhausted/concurrent allocation is blocked; allocation audited; label not printed without approved price. |
| AC-MD-04 | Authorized catalog user and referenced masters. | Required bilingual/product data and up to five images are submitted. | Product card persists every listed PRD field and displays role-safe values/images. | Missing/invalid field, excessive image, unsafe file, or unauthorized cost is rejected with no partial unsafe write. |
| AC-MD-05 | A product has colour/size/character/age. | User searches/reports or views inventory. | Attributes filter/report the product but create no variant or separate balance. | UI/import cannot create implicit variant stock; configuration changes audited. |
| AC-MD-06 | Customer policy and purpose-authorized actor. | A unique phone profile with consent/contact/children is saved/viewed. | One customer links authorized purchase/party history, separated wallets, loyalty, and gift activity. | Duplicate phone or cross-wallet exposure is blocked and audited. |
| AC-PRC-01 | Approved Excel file and import permission. | User maps columns, chooses Create Only/Update Existing, validates, reviews, and approves. | Valid rows write only after approval; invalid rows do not write; downloadable error list identifies each rejected row. | Unsafe file, bad mapping, duplicates, missing references, or unauthorized mode fails safely and is audited. |
| AC-PRC-02 | Approved product setup permits types. | User creates standard/composite/service product. | Only applicable fields/rules display and persist; transaction behavior matches approved type. | Unsupported/missing composition or unsafe post-use type change is blocked/audited. |
| AC-PRC-03 | Active product, list, and location. | Price is proposed from card/import/purchase context or cost changes. | Proposal records source; approved sale price is not automatically changed by purchase-cost change. | Direct active-price overwrite/invalid location/amount is blocked and audited. |
| AC-PRC-04 | Submitted price version and configured approval. | Authorized Pricing Officer approves. | Immutable approved version activates for future use; historical invoices/sales retain original values. | Unauthorized/stale/concurrent approval or editing approved version is blocked; before/after audited. |
| AC-PRC-05 | A location has existing active price and remaining stock. | New version is approved. | Exactly one active shelf price exists for product/location and applies to remaining balance/future transactions. | Duplicate active price or inconsistent effective interval rolls back and surfaces conflict. |
| AC-PRC-06 | Approved price version and remaining quantity by location. | Queue is generated and labels printed/reprinted. | Required quantity equals remaining stock per location; output uses approved price/authorized branch exception. | Wrong location/unapproved price/excess unauthorized print is blocked; every print/reprint/reason audited. |
| AC-PRC-07 | Product lacks approved sale price. | User receives, views, attempts sale, or attempts label print. | Receipt is allowed; UI shows zero and `Pricing Pending`; sale and label print are blocked. | Clear non-destructive warning; no sale/payment/stock-out effect. |
| AC-PRC-08 | Open-price policy, bounds, and explicit permission. | User enters an open price. | UI shows reference/min/max, accepts in-range value and required reason, recalculates, and audits full context. | Out-of-range/missing reason/unauthorized/offline use is blocked without losing cart. |

## Purchasing and Inventory

| ID | Given | When | Then | Failure / Permission / Audit / Print |
|---|---|---|---|---|
| AC-PUR-01 | Authorized Purchasing Officer. | Supplier is maintained or reviewed. | Contact/status/terms/invoices/returns/last prices are available within scope. | Duplicate/unsafe deletion/cross-scope access blocked; changes audited. |
| AC-PUR-02 | Product has preferred supplier and purchases from actual suppliers. | Preference later changes. | Every invoice retains actual supplier historically; current preference changes only future context. | Historical supplier rewrite blocked; preference before/after audited. |
| AC-PUR-03 | Valid supplier/store/products. | PO progresses. | Supports at least Draft, Submitted, Partially Received, Received, Cancelled, Closed with correct allowed transitions. | Invalid skip/backward/edit-terminal/unauthorized cancel blocked; states audited/printable. |
| AC-PUR-04 | Authorized entry/import and receiving store. | Purchase invoice with items, quantities, costs, discounts if used, optional tax is validated. | Valid draft/submission accurately shows totals and source; import errors are isolated. | Duplicate/invalid row/store/supplier/amount or unsafe file blocked with no stock effect. |
| AC-PUR-05 | Valid submitted invoice and current locked balances/cost. | Authorized approval occurs. | Atomic approval increases selected-store stock, posts auditable movement, updates weighted-average cost, and leaves sale price unchanged. | Concurrency/formula/authorization failure rolls back all effects; document remains unapproved. |
| AC-PUR-06 | Eligible on-hand stock and an approved purchase-invoice-line reference for every Phase 1 return line. | Supplier return is approved. | Referenced immutable return reduces the correct store stock at the original source-line unit cost and preserves cost/supplier history; print shows the source reference and cost basis. | Missing source line, excess stock, wrong supplier/store, invalid state, or direct edit blocked; movement and approval records audited. |
| AC-INV-01 | Authorized user and inventory data. | Product/store is searched/filtered. | On-hand, available, in-transit, reserved where applicable, reorder, and movements display consistently and paginate. | Cross-scope/cost leakage or unbounded load blocked; export permission enforced. |
| AC-INV-02 | Branch has assigned selling store. | Cashier searches another branch and attempts sale. | Availability may display for service, but cart/approval can consume only assigned selling-store stock unless an approved manager override exists. | Unauthorized store sale blocked; override highlighted/audited. |
| AC-INV-03 | Valid source/destination and stock. | Transfer goes Draft→Submitted→Approved→Dispatched/In Transit→Partially Received/Received or Difference Review. | Actual receipt and shortage/damage/refusal are separate; balances/in-transit reconcile. | Invalid transition, double dispatch/receipt, insufficient stock, or unauthorized scope rolls back/audits. |
| AC-INV-04 | Authorized stock document actor and approved reason. | Entry/exit/exchange/adjustment is submitted/approved. | Document stores reason/store/items/quantities/responsible/approval and creates exact movements. | Missing data/invalid state/direct balance edit blocked; approval audited. |
| AC-INV-05 | Default negative-stock block and optional store policy. | An operation would go negative. | It is blocked by default; only explicit authorized override proceeds with visible warning/reason/audit. | Missing policy/right/reason fails with no movement. |
| AC-INV-06 | Product fractional flag. | Fractional quantity is entered. | It is accepted only for enabled product and stored at approved precision. | Fractional quantity for disabled product or excessive precision is rejected. |
| AC-INV-07 | Assigned Counter and approved full/partial scope. | User scans/manually enters/repeats counts and submits. | Session records every in-scope count/recount, discrepancies, and report without stopping sales. | Out-of-scope/duplicate/unauthorized approval blocked; edits audited. |
| AC-INV-08 | Count captures reference balance while movements continue. | Manager reconciles verified quantity. | Calculation includes subsequent movements and produces correct referenced adjustment only after approval. | Stale/missing movement window, race, or counter self-approval blocked and reviewed. |
| AC-INV-09 | Count has uncounted in-scope items. | Session is submitted. | Items enter review and are never automatically zero; Counter and Warehouse Manager approvals precede any adjustment. | Implicit zero/one-person approval blocked and audited. |

## POS, Returns, Customers, and Shifts

| ID | Given | When | Then | Failure / Permission / Audit / Print |
|---|---|---|---|---|
| AC-POS-01 | Cashier with active shift and assigned selling store. | User scans/searches, changes permitted quantity, selects/registers customer, suspends/retrieves, or prints. | Dedicated POS remains fast, cart/totals visible, and supported thermal/A4 output is produced for approved sale. | Unauthorized qty, stale/unpriced/wrong-store stock, invalid customer, or recoverable error preserves cart and blocks posting. |
| AC-POS-02 | Valid checkout. | Sale is approved once. | Sale stores branch, selling store, cashier, drawer, shift, optional customer, payments, and stock-movement references. | Missing linkage/duplicate submit/concurrency failure rolls back and audits conflict. |
| AC-POS-03 | Cash/manual electronic methods configured. | Payment is recorded; electronic evidence uploaded. | Exact payment links to sale/shift; safe evidence is protected and authorized; no gateway event is implied. | Missing/unsafe/oversized evidence, unauthorized method/access, or duplicate payment blocked/audited. |
| AC-POS-04 | Authorized tax selection and current tax version. | Cashier chooses tax or no tax for invoice. | Unified normal sequence is used and totals/print reflect chosen optional tax exactly. | Unauthorized/stale/invalid tax or total mismatch blocks approval. |
| AC-POS-05 | Customer/group or item/invoice discount is eligible. | Another discount targets same amount. | UI blocks stacking or asks to replace; final amount has only one discount type. | Cumulative stacking/unauthorized replacement blocked; source/choice audited. |
| AC-POS-06 | Approved sale with/without item discount/tax. | Thermal/A4 invoice prints. | Each line shows item/qty/original price; discount next line and net; totals show gross, discount, net, optional tax, final. | Missing/incorrect snapshot prevents final print approval/reports defect; reprint audited. |
| AC-POS-07 | Approved eligible sale. | Gift Receipt is issued/used. | Output has no prices and uniquely identifies eligible original sale for return/exchange. | Price leakage, invalid/reused reference, or unauthorized reprint/use blocked/audited. |
| AC-RET-01 | Original invoice or Gift Receipt and return policy. | Return/exchange starts. | Reference, actor, policy, eligible lines/value/quantity are validated before action. | Missing/invalid/overused/ineligible reference or unauthorized exception is blocked. |
| AC-RET-02 | Valid inspected eligible return. | Same-item/different-item exchange, cash refund, or Gift Card settlement is chosen. | Exact return/replacement stock and financial difference/eligible value post atomically with references. | Unsupported/incorrect/duplicate settlement or concurrency failure rolls back. |
| AC-RET-03 | Returned item. | Operator records inspection and seeks required approval. | Sellable item returns to stock; rejected/damaged item uses separate non-saleable/damage process. | Missing condition/approval or direct stock return blocked; condition/evidence/audit retained. |
| AC-RET-04 | Approved Gift Card policy/source. | Card is issued, checked, used, expired, or voided. | Unique ID, original/current balance, history, validity, holder/reference, and permissioned atomic ledger movement remain traceable. | Duplicate/expired/void/overuse/concurrent/direct balance edit blocked and audited. |
| AC-CUS-01 | Existing customer profile. | Authorized actor views retail/party history. | One identity and appropriately scoped histories display without combining financial balances. | Unauthorized activity/sensitive data blocked/redacted. |
| AC-CUS-02 | Product Wallet and Party Wallet data. | Cashier or Party Manager opens customer finance/settles. | Cashier can access only Product Wallet; Party Manager only Party Wallet; ledgers/reports remain separate. | Direct URL/query/export/cross-settlement is denied server-side and audited. |
| AC-CUS-03 | Approved shared loyalty rules and online eligible source. | Points earn/redeem/expire/adjust. | One customer balance posts immutable source-linked activity-rule movement with approval/expiry. | Insufficient/expired/duplicate/concurrent/offline redemption or direct edit blocked. |
| AC-CUS-04 | Customer transactions across modules. | History/ledger movement is viewed. | Sales, parties, payments, returns, gifts, points and respective wallet entries retain source-document links. | Orphan/unauthorized/unbounded history is prevented/reported. |
| AC-CSH-01 | Assigned drawer and Cashier with no conflicting shift. | Shift opens and POS/cash activity occurs. | Opening balance stored; every transaction/movement links to active shift/drawer. | Second active/conflicting shift or unlinked posting blocked. |
| AC-CSH-02 | Open shift ready to close. | Cashier enters actual cash/electronic totals. | Expected values are not visible before irrevocable submission. | Any pre-submit leak is a critical failure; missing/duplicate submission blocked/audited. |
| AC-CSH-03 | Blind actual totals submitted. | System calculates variance and Manager/Reviewer opens it. | Authorized role sees expected/actual shortage/overage details; Cashier access follows approved post-submit policy only. | Unauthorized view/settlement/edit blocked; review audited. |
| AC-CSH-04 | Reviewed shift/day data. | Closing outputs print. | Thermal concise receipt and A4 detailed report reconcile methods, movements, shifts, drawers, and variances. | Mismatch/missing source blocks sign-off; print/reprint audited. |

|---|---|---|---|---|

| AC-PTY-05 | Confirmed party and released operating order. | Resources are reserved, consumables issued, or controlled lines added/removed. | Party resources/stock/actuals update through referenced actions until completion. | Conflict, insufficient party stock, retail source, missing approval, or post-complete edit blocked/audited. |
| AC-PTY-06 | Operations/assets/payments ready and Party Wallet policy satisfied. | Authorized final close occurs. | Final invoice, payment reconciliation, Party Wallet settlement, remaining amount/credit, final status/receipt commit atomically. | Unresolved asset/operation, Product Wallet, totals/race/permission error rolls back; final immutable. |

| AC-AST-02 | Active asset and party interval. | Reservation/check-out/return is attempted. | Overlap is atomically blocked; valid reservation and source-linked checkout/return documents are recorded. | Race/wrong party/location/state/duplicate action blocked and audited. |
| AC-AST-03 | Asset before/after party. | Responsible user records condition and transitions state. | Only Available, Reserved, Checked Out, Under Inspection, Damaged, Under Maintenance, Retired, Lost transitions allowed by map. | Missing condition/invalid skip/backward/unauthorized state blocked; before/after retained. |

| AC-AST-05 | Released party order and party-store consumables. | Quantity is issued/consumed or eligible unused quantity returned. | Approved issue reduces party-store stock and source-linked permitted return increases it. | Retail/wrong store, excess return, insufficient stock, or unsourced/direct movement blocked. |

## Reports and Non-functional Requirements

| ID | Given | When | Then | Failure / Permission / Audit / Print |
|---|---|---|---|---|
| AC-RPT-01 | Authorized scope and source transactions. | Dashboard filters by date/branch/scope. | All listed sales, invoice, average, method, performance, drawer, variance, stock, purchasing, party, and top-entity widgets reconcile to sources. | Undefined formula, mismatch, cross-scope data, slow unbounded query, or unauthorized margin/cost fails review. |
| AC-RPT-02 | Alert source conditions. | User opens/filter alerts. | Low/zero/unpriced/pending price/transfer/count/invoice/shift/party/balance/asset issues appear and link to authorized source. | Stale/duplicate/unauthorized alert detail is prevented; dismissal/action audited where applicable. |
| AC-RPT-03 | Authorized report group/filter/format. | User views or exports PDF/Excel. | Available date/branch/store/user/supplier/product/category/method/customer/party/document filters work; report groups include all PRD minimum content; export matches view/source. | Unauthorized field/scope, excessive range, formula injection, unsafe artifact access, or totals mismatch blocked/audited. |
| AC-NFR-01 | Sensitive event occurs. | Transaction commits. | Audit captures user, time, session/device when available, branch/store, source, reason if required, protected before/after and all mandatory event types. | Missing required audit rolls back or raises a critical integrity incident; audit cannot be edited/deleted. |
| AC-NFR-02 | Approved document. | User attempts change/cancel/reverse/return/adjust. | Direct edit/delete is blocked; permitted correction creates source-linked immutable document/movement preserving original. | Unauthorized/unreferenced correction or original mutation blocked/audited. |
| AC-NFR-03 | User lacks exact server permission/scope. | Hidden control is called directly through request/action. | Server denies safely with no data/effect; UI shows permission-denied state without leaking existence. | Any action based only on hidden UI is a critical failure and audited. |
| AC-NFR-04 | PWA/auth/attachment/offline scenario. | User authenticates, validates, uploads evidence, queues/synchronizes permitted transaction. | Role-scoped secure session, server validation, protected storage, expiring device-bound local data, idempotent safe sync and conflict review operate as policy. | Unsafe upload/session, prohibited offline action, silent overwrite, duplicate posting, or stale auth blocked/audited. |
| AC-NFR-05 | High-volume list/report. | User searches/filters/sorts/pages. | Scope is applied first; results are searchable/filterable and server-paginated or equivalently bounded with responsive states. | Unbounded browser load, N+1 severity, arbitrary sort/filter, or cross-scope result fails acceptance. |
| AC-NFR-06 | Concurrent document approvals/issues. | Two requests seek a number. | Atomic configured sequence produces unique sequential scoped numbers and idempotent retry cannot duplicate document. | Collision/gap handling follows policy; duplicate approved number rolls back and is critical/audited. |
| AC-NFR-07 | Phase 1 module or future extension boundary is reviewed. | Architecture/data/reference changes are proposed. | One modular monolith preserves retail/party/wallet separation and immutable source history without unused distributed complexity. | Microservice/headless/separate ordinary UI API or boundary-breaking change is rejected unless a new owner decision supersedes policy. |
